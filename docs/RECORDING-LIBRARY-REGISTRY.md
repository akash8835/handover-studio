# Recording library reliability
Per-authenticated-workspace SQLite metadata and library rows serialize private API requests. Original video/DOM payloads remain in existing KV storage; metadata overlay and library summary commit in one SQL transaction. Customer selection comes from verified session/device principal, never client header. Public publication/snapshot authority stays unchanged; private-source fallback reads overlay. No automatic media deletion. No paid plan or billing change.
Initial global mode is shadow. Owner-only same-origin migration controls can freeze new writes and drain workspace requests, import SHA-verified source metadata into an empty registry, export rows, and switch active only after source and viewer readbacks. Import excludes video/events and preserves links; missing/changed source fails. SQL failures do not fall back to stale legacy metadata. Prepared publication metadata tied to exact snapshot identity permits recovery after a public commit and private SQL failure.
Free quotas still apply. Migration is not larger media storage or unlimited capacity. Current free-customer cap remains20; owner exemption remains tied to authenticated owner. Library SQL rows avoid a single2MB array, but API response and isolate memory remain bounded by platform.
Acceptance: actual local SQLite worker concurrent8uploads/comments, customer/device isolation, original bytes, same-link edited media/title, frozen admin controls/nonempty import, SQL failure/recreated-handler staleness/recovery; full96checks with95passing and known deferred managed-auth expectation. Rollback merges current metadata into original legacy payloads, never blindly restores an old library list.
